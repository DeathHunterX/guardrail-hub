# Improvement Discoveries

Records of improvements observed during implementation and deliberately **not** implemented then, per [governance/improvement-discovery.md](../improvement-discovery.md). Established by [RFC-0005](../rfcs/0005-improvement-discovery.md).

Named `NNNN-short-slug.md`, append-only — the same record-series shape as [`rfcs/`](../rfcs/README.md), in the module that governs it.

## What belongs here

An observation about the repository that was true at the moment of discovery, was outside the scope or authority of the work in flight, and would otherwise be lost. The [record contract](../improvement-discovery.md#the-record) lists the fields.

## What does not

This is **not a backlog**. No assignee, no priority, no effort estimate, no due date, no `Open`/`Done`. A record sitting at `Recorded` is a fact that remains true, not a ticket going stale. If an entry would be more useful as work, it has already been promoted — into a plan, an [ADR](../../decisions/README.md), or an [RFC](../rfcs/README.md) — and its state says so.

Also not here: corrections about *how to work in this repository* (that is [Memory](../../memory/README.md)), facts about current repository state (that is [`intelligence/`](../../intelligence/README.md)), and anything a `ponytail:`-style inline comment already carries at the site — a record that duplicates a comment two files over is the duplication [Knowledge: Granularity](../../knowledge/README.md#granularity) warns about.

## Lifecycle

`Recorded → Promoted | Superseded | Declined`. See [the state diagram](../improvement-discovery.md#lifecycle). `Declined` carries its reason and is the most valuable terminal state — it stops the same discovery being re-derived every year.
